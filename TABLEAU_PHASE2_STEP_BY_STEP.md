# DDOT Tableau Road Safety — Phase 2 Implementation Guide
**Version:** 2.0 | **As of:** 2026-10-10 | **Audience:** DDOT Vision Zero, traffic safety, GIS, performance management
**Purpose:** Rebuild a defensible corridor-screening dashboard in Tableau Desktop. This is a POC, not a published DDOT performance statement.

## 1. Deliverables & what is live
- `ddot_crash_dashboard.html`: browser version of the Tableau dashboard. Served locally (`python3 -m http.server 8000`, then http://localhost:8000/ddot_crash_dashboard.html) it reads `data/phase2/ddot_crashes_enriched.csv` and `ddot_hin_geometry.geojson`; opened as a file or with `?source=live` it downloads live DCGIS crash and HIN data and does the 35 m HIN match in the browser.
- `DDOT_Crash_Safety_Dashboard.twbx`: packaged Tableau workbook generated by `build_tableau_workbook.py` from the `data/phase2` output.
- `download_ddot_data.py`: authoritative, normalized *Crashes in DC* extractor.
- `enrich_ddot_safety.py`: downloads DDOT HIN, AADT, work-order layers; spatially screens lines and points; exports Tableau CSVs and a browser JSON bundle.
- `TABLEAU_BUILD_GUIDE.md`: retained Phase 1 instructions.

Real crash data is not checked in; run the extractors on a machine with network access (`download_ddot_data.py` → `enrich_ddot_safety.py` → `build_tableau_workbook.py`) to produce `data/phase2` and the `.twbx`.

## 3. Generate Tableau extracts (step by step)

Install Python 3.9 or newer (all transformation scripts use the standard library). Place both `.py` scripts in the same working directory.

```bash
# Step A — two (or more) full comparable reporting years.
python download_ddot_data.py --start 2023-01-01 --end 2026-09-30 --output ddot_crashes_2023_2026.csv

# Step B — join with actual DCGIS network and DDOT work-order layers.
python enrich_ddot_safety.py --crashes ddot_crashes_2023_2026.csv --outdir ddot_phase2_output

# Step C — optional ONLY after documented review of installation data.
python enrich_ddot_safety.py --crashes ddot_crashes_2023_2026.csv \
  --verified-projects verified_safety_projects.csv --outdir ddot_phase2_output
```

**If the source service is blocked by your firewall**, ask GIS administrators for GeoJSON FeatureCollections corresponding to the *exact* three URLs above, using output spatial reference EPSG:4326, then:

```bash
python enrich_ddot_safety.py --crashes ddot_crashes_2023_2026.csv \
  --hin-geojson hin.geojson --aadt-geojson aadt.geojson \
  --workorders-geojson workorders.geojson --outdir ddot_phase2_output
```

The standard exporter retrieves `objectIds`, queries them in batches of 250, and deduplicates. The crash source exporter paginates crash records. Always compare exported row counts against the service's current reported count because live data can change during extraction.

### Output contract
1. `ddot_crashes_enriched.csv` — crash-level fact table. Important fields: `crash_id`, `report_date`, `ward`, `ksi_crash`, `fatalities`, `major_injuries`, `hin_corridor_id`, `hin_tier`, `hin_distance_m`, `corridor_aadt_context`, `corridor_aadt_coverage_pct`.
2. `ddot_hin_corridors.csv` — corridor dimension. `corridor_id`, `hin_tier`, `hin_miles`, `aadt_context`, `aadt_coverage_pct`, `aadt_min_year`, `aadt_max_year`. Its length-weighted AADT reflects matched HIN segments only.
3. `ddot_hin_geometry.geojson` — HIN lines for Tableau spatial layer.
4. `ddot_safety_workorders.csv` — independent Cityworks operational events matched to nearest HIN within 50m.
5. `ddot_verified_projects.csv` — reviewed installation evidence, possibly empty.
6. `ddot_safety_bundle.json` — single-file JSON bundle of all relevant tables and HIN geometries (not used by `ddot_crash_dashboard.html`).
7. `ddot_data_quality.json` — provenance, counts, matched coverage, buffer thresholds.

## 4. Spatial join logic and QA

- **Crash → HIN:** nearest eligible polyline within **35 meters** using a local tangent-plane point-to-segment distance. A feature can be unassigned. Do not infer a "crash on the corridor" with higher certainty than the match supports.
- **HIN → AADT:** nearest eligible line within **25 meters** from representative HIN segment midpoint. Prefer the same `ROUTEID` when available; otherwise identify the match as *proximity-only*. Each HIN segment contributes its approximated length to an indicative **length-weighted AADT** for the corridor.
- **Work orders → HIN:** nearest eligible line within **50 meters**. Work-order status is kept verbatim.
- **HIN tier:** use `TIER_1`, `TIER_2`, `TIER_3`. The tier hierarchy in the output prefers Tier 1 where several HIN segments share an ID.
- **Corridor identity:** `CORRIDORID` from DDOT. Without this, each unkeyed line gets its own synthetic ID to prevent false grouping.
- **Missing geometry:** point records with absent/out-of-DC coordinates never get a line match.
- **Project installations:** only reviewed rows with supported installed/completed status **plus** `install_date` **plus** `verification_source` count as verified installs. Do not join safety work-order "Closed" statuses as delivered projects.

**Important limitations:** Midpoint AADT matching does not establish continuous traffic count coverage for every route measure; parallel streets and junction proximity can lead to false matches. Multiple HIN events may overlap; the corridor-length summation can overstate distinct network miles. Do not use these figures to compute an official rate per million vehicle-miles traveled. A complete exposure model would need temporally matched AADT along each unique roadway segment, accurate network lengths and year-specific VMT.

## 5. Tableau Desktop — create the model

### 5.1 Data connection
1. Launch Tableau Desktop → **Connect → Text File** and open `ddot_crashes_enriched.csv`.
2. Set `report_date` to **Date**, `fatalities`, `major_injuries`, `ksi_crash` to **Whole Number**, `latitude`/`longitude` and `hin_distance_m` to **Decimal**, `crash_id` and `hin_corridor_id` to **String**. If Tableau interprets blank tiers as nulls, keep them null.
3. In the **Data Source** logical model, drag in `ddot_hin_corridors.csv`. Add a **Relationship** on `hin_corridor_id = corridor_id` (many crash facts to one corridor ID). Confirm one `corridor_id` per corridor row.
4. Add `ddot_safety_workorders.csv` separately, ideally as a **second data source** for an independent work-order status worksheet. It is a second fact table: do not physically join it to crashes because that multiplies both counts.
5. Add `ddot_verified_projects.csv` as another independent source for any installation summary. Empty extracts should show "Not available", not false zero installations.
6. To draw the HIN lines, choose **Connect → Spatial File** and open `ddot_hin_geometry.geojson`; make a separate HIN network map worksheet. You may build spatial mark layers if your Tableau version's data model supports geometry and multiple layers cleanly. Keep the crash point map on its own worksheet if separate data sources prevent safe shared mark layers.
7. Data → Create Extract → save refreshable `.hyper`. Retain source snapshot date for audit.

### 5.2 Data relationships—granularity audit
- `ddot_crashes_enriched.csv`: one row per `crash_id` (verify duplicates before treating as unique).
- `ddot_hin_corridors.csv`: one per `corridor_id` (a dimension).
- `ddot_safety_workorders.csv`: one row per `workorder_id` (independent event type).
- `ddot_verified_projects.csv`: one per `project_id` (independent project fact).
- Never use a row-level join from both work orders and crashes to corridors that duplicates them. For comparisons, aggregate each fact table before combining or use relationships with validated grain.

## 6. Tableau calculated fields — paste into Create Calculated Field

### 6.1 Parameters
Create **`p_Report_Cutoff`** as Date, value e.g. `2026-09-30`; use parameter control.
Create **`p_Tier`** as String, list: `All`, `HIN only`, `Tier 1`, `Tier 2`, `Tier 3`, `Outside HIN`.
Optionally create **`p_Min_HIN_Match_Quality`** for future verified attribution rules.

**Current comparable window** (boolean):
```tableau
YEAR([report_date]) = YEAR([p_Report_Cutoff])
AND [report_date] >= MAKEDATE(YEAR([p_Report_Cutoff]), 1, 1)
AND [report_date] <= [p_Report_Cutoff]
```

**Prior comparable window** (boolean):
```tableau
YEAR([report_date]) = YEAR([p_Report_Cutoff]) - 1
AND [report_date] >= MAKEDATE(YEAR([p_Report_Cutoff]) - 1, 1, 1)
AND [report_date] <= DATEADD('year', -1, [p_Report_Cutoff])
```
For Feb 29, confirm the expected prior-year cutoff (Feb 28) with business stakeholders.

**Tier display** (string):
```tableau
IF ISNULL([hin_tier]) THEN "Outside HIN"
ELSEIF INT([hin_tier]) = 1 THEN "Tier 1"
ELSEIF INT([hin_tier]) = 2 THEN "Tier 2"
ELSEIF INT([hin_tier]) = 3 THEN "Tier 3"
ELSE "Outside HIN"
END
```

**Tier parameter condition**:
```tableau
CASE [p_Tier]
 WHEN "HIN only" THEN [Tier display] <> "Outside HIN"
 WHEN "Tier 1" THEN [Tier display] = "Tier 1"
 WHEN "Tier 2" THEN [Tier display] = "Tier 2"
 WHEN "Tier 3" THEN [Tier display] = "Tier 3"
 WHEN "Outside HIN" THEN [Tier display] = "Outside HIN"
 ELSE TRUE
END
```
Add this as a true-valued filter to all crash-based worksheets.

**Current KSI crash counter**:
```tableau
IF [Current comparable window] THEN INT([ksi_crash]) ELSE 0 END
```

**Prior KSI crash counter**:
```tableau
IF [Prior comparable window] THEN INT([ksi_crash]) ELSE 0 END
```

**Current fatal persons**:
```tableau
IF [Current comparable window] THEN INT([fatalities]) ELSE 0 END
```

**Current major-injured persons**:
```tableau
IF [Current comparable window] THEN INT([major_injuries]) ELSE 0 END
```

**Comparable KSI % change** (aggregate):
```tableau
IF SUM([Prior KSI crash counter]) = 0 THEN NULL
ELSE
 (SUM([Current KSI crash counter]) - SUM([Prior KSI crash counter]))
 / SUM([Prior KSI crash counter])
END
```
Format as percentage. Never show 0% when no prior-year denominator exists.

**Current crash count (deduplicated)**:
```tableau
COUNTD(
 IF [Current comparable window] THEN [crash_id] END
)
```

**KSI near HIN**:
```tableau
IF [Current comparable window] AND NOT ISNULL([hin_corridor_id])
 AND [hin_corridor_id] <> ""
THEN INT([ksi_crash]) ELSE 0 END
```
For fatal persons on HIN replace `ksi_crash` with `fatalities`; *person* and *crash* denominators are never interchangeable.

**KSI crash count per HIN corridor mile — screening metric only**:
```tableau
IF ATTR([hin_miles]) > 0 THEN
 SUM([Current KSI crash counter]) / ATTR([hin_miles])
END
```
Note: `ATTR([hin_miles])` must be unique in the view, usually with `[corridor_id]` on Detail. This is NOT traffic-exposure normalized and should not be labeled as an official safety risk rate.

**HIN AADT coverage** (corridor dimension):
```tableau
IF SUM([hin_miles]) > 0 THEN
  SUM([aadt_covered_miles]) / SUM([hin_miles])
END
```
Use only a corridor-grain worksheet without crash-level facts in the view to avoid double counting.

**Map point**:
```tableau
MAKEPOINT([latitude], [longitude])
```

## 7. Tableau worksheet build steps

### WS01 — Current-year KSI crash card
1. On `ddot_crashes_enriched` source create new sheet → rename `01 KSI Current`.
2. Marks = Text. Drag `Current KSI crash counter` to Text → measure aggregation **SUM**.
3. Put Tier parameter condition = True on Filters. Format numeral with commas and a short "KSI crashes" subtitle.
4. Duplicate → change to `Prior KSI crash counter` for `02 KSI Prior`.
5. Duplicate → use `Comparable KSI % change` for `03 KSI YoY`. Show an em dash or "N/A" when NULL.
6. Duplicate → use `KSI near HIN` for `04 HIN KSI`.

### WS05 — HIN corridor KSI ranking
1. Drag `corridor_name` and `corridor_id` to Rows.
2. Drag `SUM(Current KSI crash counter)` to Columns.
3. Filter to non-null HIN IDs, sort descending; Top 12 by KSI.
4. Set Marks = Horizontal Bar; color by tier; tooltip: corridor ID, tier, report period, KSI count, fatal persons.
5. Create a dashboard **Filter Action** on selection to drive crash map and year-comparison trend.

### WS06 — HIN crash-location map
1. On crash fact source use `MAKEPOINT([latitude],[longitude])`, Marks = Circle.
2. Set Geometry to Detail, add `Tier display` on Color and `Current KSI crash counter` on Size.
3. Restrict to non-null latitude/longitude and current comparable window.
4. Tooltip: crash date, ward, nearest street, fatal/major persons, corridor ID, HIN distance and "proximity only".
5. To show HIN polylines, build separate `HIN Network` spatial worksheet using GeoJSON Geometry, then either combine as Tableau map mark layers where supported or place the HIN map adjacent. Do not claim an overlay that your Tableau version cannot implement cleanly.

### WS07 — Comparable month-by-month trend
1. Put `MONTH(report_date)` **as discrete month-of-year (Jan-Dec)** on Columns (do not use month-year).
2. Put `SUM(Current KSI crash counter)` and `SUM(Prior KSI crash counter)` on Rows with Measure Names / Measure Values for side-by-side bars.
3. Filter record dates to the two comparable windows using `Current comparable window OR Prior comparable window`.
4. Format current red (`#C74853`) and previous blue (`#3B89A1`), show explicit year labels.
5. Do NOT apply a raw current-year-only `report_date` quick filter to this sheet: it would remove previous-year records.

### WS08 — AADT bands / coverage
1. Use the independent `ddot_hin_corridors` source.
2. Create `[AADT band]`:
```tableau
IF ISNULL([aadt_context]) THEN "Unmatched"
ELSEIF [aadt_context] < 10000 THEN "<10k"
ELSEIF [aadt_context] < 25000 THEN "10k–24,999"
ELSEIF [aadt_context] < 50000 THEN "25k–49,999"
ELSE "50k+"
END
```
3. Put AADT band on Rows and `COUNTD(corridor_id)` on Columns. Show coverage % and AADT year range in tooltip.
4. Place total weighted coverage ratio in separate worksheet; do **not** display an exposure-normalized crash rate unless VMT model passes separate validation.

### WS09 — Safety work orders
1. Use independent `ddot_safety_workorders.csv` source.
2. Place `[status]` on Rows, `COUNTD([workorder_id])` on Columns.
3. Use `matched_corridor_id` for a corridor context filter, but explicitly label **"work-order activity"**.
4. Distinguish `closed_date` from a certified field installation date.
5. When the reviewed projects table has actual rows, build a separate completed-projects count with `SUM([verified_installed])`, and source tooltips; no automatic treatment efficacy claim.

### WS10 — Corridor inventory
1. Use the corridor dimension `ddot_hin_corridors.csv`.
2. Place `corridor_name`, `corridor_id`, `hin_tier` on Rows.
3. Display `MIN(hin_miles)`, `MIN(aadt_context)`, `MIN(aadt_coverage_pct)`, `MIN(aadt_min_year)`, `MAX(aadt_max_year)` (one row per corridor).
4. If adding crash KSI summary, validate the relationship; don't cross-join work orders and crash facts.
5. Use action to cross-filter corridor details.

## 8. Tableau dashboard assembly
- Size: start at 1440×1000; use tiled horizontal + vertical containers.
- Top header: title, data refresh timestamp, source badges and methodology note.
- Filter row: date-cutoff parameter, HIN tier, ward, corridor.
- KPI row: current KSI, prior KSI, comparable change, HIN KSI, HIN AADT coverage.
- Middle row: corridor ranking (left) and crash/HIN maps (right).
- Lower row: year-comparison chart, AADT distribution, work-order activity; bottom full-width corridor inventory.
- Global controls: parameter actions should affect crash views and comparable measures without removing prior-year data.
- Add dashboard actions: select corridor in ranking → Filter crash map and trends, **not** the independent unjoined work-order worksheet unless mapped through a validated corridor bridge.
- Add a footer tooltip/Info sheet with data vintage, match buffers, and "not official" disclaimer.
- Accessibility: high contrast, keyboard-operable filters, visible zero vs unavailable, color + labels for injury severity.

## 9. Acceptance test / data audit sign-off

| Test | Expected result |
|---|---|
| Crash count & deduplication | `COUNTD(crash_id)` matches normalized unique source IDs for chosen window |
| KSI semantics | `SUM(ksi_crash)` counts crashes; fatalities/major injuries count people |
| Comparable windows | Current and prior both Jan 1 through same month/day; leap-day policy reviewed |
| Spatial assignments | Distances <= threshold and unmatched records explicitly retained |
| HIN tier distribution | Count of tier 1/2/3 segments reconciled to source extracted `TIER_*` flags |
| AADT | Matched route IDs screened and max/min years displayed; no traffic-rate claim |
| Safety activity | Work orders are counted separately; "Closed" never implies installed |
| Verified projects | No installation without status + installation date + verifiable source |
| Tableau joins | No changed crash counts after adding corridor dimension or work-order source |
| Data completeness | Reportdate coverage (max date), crash ID duplicates, missing lat/lon, GIS extract audit |
| Browser prototype | Source JSON loads; filtering, bars, map and CSV export succeed |
